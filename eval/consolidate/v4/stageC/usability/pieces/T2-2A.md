# Empty nodes in graph diffusion: what filling them in costs

Suppose you want a map of a research literature. Each paper becomes a point described by a vector, here a 768-number embedding from a language model (SPECTER2) that summarises the paper's text. Citations link the points into a graph. Before projecting everything into two dimensions and clustering it, you smooth the vectors over the graph, so that papers tied together by citations drift closer than their text alone would put them.

The smoothing step is graph diffusion. A common form, APPNP, runs in rounds. In each round every node replaces its vector with a blend: most of the weight goes to the average of its neighbours, and a fixed share (0.3 in the pipeline discussed here) pulls it back towards its own starting vector, its anchor. That pull matters. Without it, repeated averaging drives every node towards the same vector, a well-documented failure called oversmoothing.

Many nodes in a citation graph have no vector. In one working pipeline of this kind, after keeping only nodes with at least two links, 3,392 nodes had no features and 1,405 had them: roughly 70% of the graph is empty. An empty node has no anchor, so the method needs a decision. Give it zeros, give it an estimate built from its neighbours, or give it nothing and let it only pass signal along.

## Does a filled-in node keep the link it carries?

Take two papers, A and B, that both cite a third paper C, which has no vector. A shared reference has long been read as evidence that two papers are related. Does the diffusion still pull A and B together once C has been filled in?

On paper, yes. Diffusion of this kind is equivalent to a random walk that either steps to a neighbour or jumps home, and a walk can pass from A through C to B, so C contributes to the similarity A and B end up with. This matches older work in network embedding (LINE, 2015) formalising the idea that nodes sharing neighbours should sit close together.

Whether the bridge survives to the final map is unshown, and three things can erode it. Um and colleagues (2025) proved that diffusion-based filling tends to produce channels whose values are nearly identical across nodes, and that such low-variance channels contribute very little downstream. A node whose vector is essentially the local average carries that kind of near-constant signal. The empty node also lacks the anchor that protects real nodes from oversmoothing. And the projection and clustering steps (UMAP and HDBSCAN here) work on local neighbourhoods; they can absorb a weak pull or treat a thin bridge as noise.

Filling with zeros has a sharper problem. Yi and colleagues (2020) showed that when missing values are set to zero, a model's output scales with the fraction of values actually observed. In an averaging step, a zero neighbour simply shrinks the average. Because APPNP reapplies every anchor in every round, a zero-anchored empty node keeps dragging its real neighbours towards the origin for the whole run, distorting the papers you have good data for.

A cleaner design exists. Feature Propagation (Rossi and colleagues, 2022), built for missing features, resets known nodes to their true values each round and lets unknown ones be set entirely by their neighbours. Its end state does not depend on how the unknowns were first filled. That suggests a masked APPNP: keep empty nodes in the neighbour-averaging so they still relay A's influence to B, but drop them from the anchor term. Nodes that route information without contributing features have precedent, in the "virtual nodes" of message-passing networks and in masked aggregation. Nobody has compared zero anchors, estimated anchors and masked conduits head to head. Two details need care: whether a masked node still counts towards its neighbours' degree, which changes the averaging weights, and whether a weakly linked node with no anchor floats loose and gets scattered by the projection.

## How much emptiness can the method tolerate?

The headline robustness figure is encouraging. Rossi and colleagues report only a 4.12% relative drop in classification accuracy with 99% of features missing. Most methods they tested did well up to about 50% missing, the gap between methods opened from around 60%, and at 90% to 99% Feature Propagation was the only feature-aware method that held up on every dataset.

Those numbers come from friendlier conditions. Values were removed at random, entry by entry, so a node rarely lost everything. The features were sparse word-count vectors. And the graphs were ones where linked nodes tend to resemble each other, which the method relies on. Later work presses on each point. Ferrini and colleagues (2026) argue that with sparse features, extra missingness barely changes how informative the features are until more than 90% are removed, so sparse benchmarks flatter robustness; methods that looked robust there failed on dense, low-dimensional features. Yun and colleagues (2024) found Feature Propagation degraded more steeply when whole nodes were missing. A dense embedding with whole nodes empty is the unfavourable case on both counts.

So 70% empty sits just past the point where methods began to diverge on easy benchmarks, under conditions that should make things worse. Read the 50–60% figure as an optimistic ceiling; no published result gives a threshold for dense features with whole-node gaps.

The obvious lever is to demand more links per node, which shrinks the empty share. It also throws away nodes and edges, including some of the bridges you wanted to keep, and nobody has measured that trade-off for citation graphs. Position probably matters too: an empty node among real neighbours is better off than one buried among other empty nodes, at the same overall share.

## What happens with a denoising step?

Pipelines like this often compress the real vectors before diffusion, here with principal component analysis (PCA) down to 100 dimensions, to strip noise. Empty nodes have nothing to compress, so denoising happens before they get any anchor. How the two steps interact is unstudied; only the pieces exist.

Morehead and colleagues (2022) found that reducing features to 100 PCA dimensions before a graph network kept accuracy intact (80.82% versus 80.98% on a standard citation benchmark), but with complete features. Yi's result means any step that changes vector magnitudes, as PCA's centring does, will interact with the shrinkage zeros cause. And in ordinary statistics, PCA run with missing entries set to zero biases the variance spectrum downwards.

Put together, the outcome could go either way. A zero anchor pulling on centred, compressed vectors might distort them more, because each kept dimension carries more relative weight, or less, because the vectors are smaller. It might also push energy into directions PCA had discarded. Denoising first is plausibly the safer order, since diffusion already smooths and denoising afterwards would smooth the estimates twice. That is reasoning, not evidence.

## What would settle it

All of this is answerable with measurements on the pipeline itself. Check whether filled-in channels have collapsed towards constant values. Test whether pairs bridged only by an empty node cluster together more often than pairs given a randomly assigned shared empty neighbour. Compare zero, estimated and masked anchors by how far they move the real nodes. Raise the link threshold in steps, tracking both reliability and how much graph is lost. And measure distortion in a way that ignores overall scale, so PCA's change in magnitudes is not mistaken for damage.
