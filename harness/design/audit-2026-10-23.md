# Harness audit, 2026-10-23

A read-only audit of the harness: the CLI, `harness-gui`, `harness-mail`, the skills, and the text
sessions pay for. Nothing in the harness was changed. This report ranks what to cut and proposes
the branches to cut it in. The evidence for each finding is in `audit-2026-10-23/findings_*.md`,
cited here by agent letter and number (e.g. B3).

## Summary

The harness works, but it carries about a log entry's worth of extra code for every log entry it
has fixed.

| | |
|---|---|
| `bin/harness` | 27,353 lines, 859 functions, ~65 subcommands, 367 flags; cites 94 log entries 288 times |
| `bin/harness-gui`, `bin/harness-mail` | 4,505 and 268 lines |
| tests | 10,877 lines, 592 tests; reach 71% of the CLI, 34% of the GUI, 84% of mail |
| functions the suite never runs | 98 in the CLI, 20 in the GUI |
| unreferenced functions | 9 (6 dead, 3 reached only by tests or the GUI) |
| live use (biblion2, 1,023 transcripts) | 24,215 `harness` calls; report, research and design: ~3,700 CLI lines, 3 calls between them |

What costs the most is not the code. In order:

1. **Sessions don't see most of their startup orientation.** Since 2026-10-06 every SessionStart
   `whoami` (median 17.8 KB) has been over Claude Code's 10,000-byte hook limit. 629 of 630
   startups got a 2 KB preview. The scope, the `next` line, rank 0's decisions, and the reviewer's
   ponytail text (0 of 92 delivered) never arrived. Sessions then run `whoami` by hand (743 calls,
   9.3 MB, 17.5% of all harness output), and the orientation still records every item as told (E1,
   E2, A5).
2. **Every `harness` call spends 0.8-0.9 s compiling the 27k-line file** before it does anything.
   That covers about 24k session calls and four hooks a turn (A1, re-measured: 0.76-0.94 s; `--help`
   1.55 s).
3. **Forced turns.** The Stop hook blocked 1,748 turn ends. Each one forces a turn that re-reads a
   median 186k cached tokens: 375M cache-read tokens in all. Only 16% of "present it" blocks led to
   `mark --done` (E4, A4).
4. **Bugs found on the way** (14, listed below). Two are live and costly. `ask_verify` refuses briefs
   whose paths contain a space, and every absolute path in this project does (F1). A check reused
   whole skips the earlier-rows merge (B3, introduced today).

The code itself has five families of mess:
- Rules written in several places that have drifted apart: "sign-off owed" five ways, owed kinds in
  five lists, "who waits on me" three ways, the check verdict four ways.
- Mechanisms a later fix replaced but never removed: the block decision workflow, the rerun/carry
  rows, the doorbell waiter, documenter auto-run, the single intermediary, `whoami --delta`.
- Copied infrastructure: the report kit is a copy of the item kit, plus four prompt builders, six
  transcript tail-readers, and seven ask-close verbs.
- Surfaces nobody uses.
- Text that restates what the CLI prints at the moment it matters.

## How this was done

- **Data, built first.** Coverage over the full suite, static reference counts, live usage from
  biblion2's transcripts, and a map of log citations. The scripts are in `audit-2026-10-23/scripts/`
  (`covfuncs.py`, `static_refs.py`, `usage.py`, `logmap.py`, and agent E's `e_*.py`).
- **Six read-only agents**, about 1.5M tokens in all. Each applied `ponytail-audit` to a slice:
  - A: lines 1-5543, core and hooks;
  - B: lines 5544-12010, marks, check, test queue, integrate;
  - C: lines 12011-18672, records, waits, briefs, sweep;
  - F: lines 18673-20109, the `ask_*` family;
  - D: lines 20110 to the end, plus the GUI and mail;
  - E: the text sessions pay for.

  The common brief is `audit-2026-10-23/brief_common.md`.
- **Spot checks.** I read or reproduced every finding marked confirmed below. "Plausible" means
  argued from the code by an agent, but not reproduced.
- **Token figures** are bytes/4. Agent E's calibration against API context growth (2.65 B per token)
  suggests real tokens run about 1.5x higher.

## Findings, ranked

The ranking puts what every session pays for first, then bugs, then speed, then code size.
"Owner" means a test or documented behaviour changes.

Tests:
- `Log191to194.test_a_wait_on_a_harness_fix_is_owed_by_nobody` is a time bomb. `settle_waits`
  compares the real CLI file's mtime with a wait backdated 10 minutes, so the test passes only
  within 10 minutes of an edit. It fails on main now.
- `TestQueue.test_priority_goes_first_and_a_lead_promotes_a_lane_job` failed in 1 of 3 full runs. It
  orders jobs by one-second timestamps separated by 1.1 s sleeps.
- Live paths with no test: `cmd_review` (88 live calls), `cmd_doctor` (469), `finding` (238),
  `ask_show` (301), `ask_amend` (53), `scaffold`, `fact --recheck`, `_session_corpus`.

## Proposed cut branches, in order

Each branch is small and passes the full suite on its own. Behaviour changes are checked against
the old CLI, as on earlier rounds.

1. **`audit-fixes`** (safe): fix 1.1, 1.2 and 1.3 with tests; defuse the time-bomb test (mock
   `harness_installed_at`); steady the flaky one.
2. **`orientation`** (owner): 2.1 and 1.4: scope out of `whoami`, told-recording only for what was
   printed, the skill and compact-template lines. This is the largest token saving, so it goes
   early.
3. **`launcher`** (owner): 3.1. It touches install and hooks, so it goes alone.
4. **`quiet`** (mostly safe): 2.4, 2.7, and 2.3's text part.
5. **`dead`** (safe): the section 4 safe list.
6. **`owed`** (owner): the `signoff_owed` predicate, the `KINDS` table, the Stop hook cooldown, one
   wait reader. This fixes 1.5 and 1.6.
7. **`speed`** (safe): 3.2-3.5, plus 1.12's single-settle guard.
8. **`check-report`** (mostly safe): one assembler, `report_at`, one verdict. This fixes 1.7.
9. **`side-sessions`** (owner): one kit, `side_prompt`, one `_bg`. This fixes 1.13, plus 2.8.
10. **`ask`** (mixed): 1.10, 1.11, `_ask_close`, 2.6, F4 and F17.
11. **Retirements**, one branch per item the owner agrees to: blocks, sweeps, rerun/carry, unused
    flags and commands, skill sections 2.2/2.5, comments in one store (1.8).

Roughly, branches 1-10 take out about 1,000 lines and most of the per-session text cost. The
retirements are another ~1,500 lines, or ~5,000 if report, research and design go.

## Decisions for the owner

1. Scope out of `whoami`, and lanes get only their own features (2.1, 2.2).
2. Stop hook: one channel per owed kind, and skip "present it" while a check is queued (2.3).
3. The bytecode launcher (3.1).
4. Retire the block decision workflow, and perhaps `blocked` itself (C1).
5. Unit and stale sweeps: run them automatically, or drop them (C4).
6. Drop test rerun/carry, `--promote`, and the `recycle` flags (B6, B13, B14).
7. Comments in one store (C3).
8. Report, research and design: freeze them now and review at the next audit (D14).
9. Path grants still meet the auto-mode classifier (log 112). Do they earn their place? (C, not
   ranked)
